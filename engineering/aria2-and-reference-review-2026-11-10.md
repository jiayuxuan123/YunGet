# 网盘速度差异与功能参考：2026-11-10

## 当前结论

用户提供的文析演示画面显示：约 2.25 GB 文件，512 工作连接、512 分段、连接上限 512，速度从 53.79 MB/s 上升到 122.77 MB/s。视频为 [BV1e2HZ6kEn8](https://www.bilibili.com/video/BV1e2HZ6kEn8)，公开元信息显示作者 zzss555、时长 62 秒、发布于 2026-10-06。当前源码比视频更新，不能把当前所有接口行为直接当成当时演示的配置。

云取查到一个确定的执行限制：设置允许 1..256，而 aria2 执行器始终截到 16。随包 ARM64 二进制实际包含 aria2-next 2.8.3；同版本官方 Windows 二进制的 `--help=stream-max-connections` 确认为 1..256。应用应保留默认 16，同时完整传递用户选择的更高上限。

这条问题只影响 aria2 分支，不能拿它解释所有 TurboDL 下载。TurboDL 自身支持 1..256，调度器使用 `Dispatchers.IO.limitedParallelism(workers + 4)`；应用继续下发 DOWNWARD 自适应与用户的慢启动设置。当前没有修改 SDK 默认并发，也没有加入网盘专用逻辑。

## 已实现

1. `Aria2CommandBuilder` 成为真实启动参数的唯一构造点，用户选择 32/64/128/256 时按该值传递，默认仍为 16。
2. 日志区分 `requestedConns` 与 `effectiveConns`，不输出鉴权头内容。
3. 标准错误合并到标准输出并持续读取，避免未读取的 stderr 管道堵塞子进程。
4. `Aria2Readout` 解析原版与 next 的真实进度和 CN。随机写入导致的文件逻辑长度不再算作传输量，工作连接数不再伪装成配置上限。
5. 续传首个计数建立测速基线，已保存字节不算成刚下载的流量；退出时工作连接归零，原始内核日志先脱敏再记录。
6. 根据 [2.8.3 官方发布契约](https://github.com/AnInsomniacy/aria2-next/releases/tag/v2.8.3)，为每个应用任务生成稳定 GID，并把恢复数据库放在该任务自己的 `aria2-state` 目录。`-c`、GID 和状态库同时保留。

旧任务没有相同身份或有效恢复数据时仍遵守内核的安全规则，不能根据文件长度强行续传。全部变更尚未发布，不能覆盖已发布的 2.7.28 安装包。

## 验证

- 修复前，真实命令构造回归在请求 32 时失败；3 项测试中有 2 项失败，认证头、限速和证书参数测试保持通过。
- 修复后：4 套件、23 项定向测试全部通过，无失败、无跳过。覆盖命令、身份恢复参数、两类 readout、稀疏文件误报、续传基线、引擎选择和原有线程提示。
- 同一官方 aria2-next 2.8.3 Windows 二进制、16 MiB 非周期测试数据、每连接 200 KiB/s、相同磁盘、独立状态目录，先预热，再进行 5 组 A/B 与 B/A 交错：

| 配置 | 中位端到端吞吐 | CV | 内核 CN 峰值 |
|---|---:|---:|---:|
| 用户选择 64，旧桥接截成 16 | 2.765 MiB/s | 1.88% | 16 |
| 用户选择 64，新桥接完整传入 64 | 6.975 MiB/s | 12.33% | 64 |

中位吞吐提高 2.52 倍。每次同时使用内核 SHA-256 校验和独立 Python SHA-256，均正确。源端活动处理器峰值新配置为 64–65，包含探测／响应交接时的瞬时重叠，不将其伪称为精确活动 socket 数。

真实进程恢复检查：先传输超过 1 MiB，再暂停并退出。旧的随机 GID 重新传输完整 16,777,216 字节；固定 GID 恢复后仅再传输 15,712,256 字节，保留此前 1,064,960 字节。最终文件 SHA-256 均正确。此项证明保留恢复身份有效，不宣称 Android 强杀／断电验收通过。

这些是 Windows 同版本内核及本地源的证据，不是手机真实网盘测速。ADB 当前无设备，未声称真机安装、测速或账号接口验收通过。

### TurboDL 分支诊断

对已发布 0.5.0.1 CLI 做了一轮同源诊断，保持 DOWNWARD 自适应开启、关闭显式慢启动，各文件都通过 SHA-256：

| 用户连接上限 | SDK 事件连接峰值 | 源端处理器峰值 | 包含 JVM 启动与退出的单次吞吐 |
|---|---:|---:|---:|
| 16 | 16 | 16 | 2.23 MiB/s |
| 64 | 64 | 64 | 5.94 MiB/s |
| 256 | 256 | 255 | 7.36 MiB/s |

这证明该本地模型中实际并发可以增长，不能把 aria2 的旧 16 上限误归到所有 TurboDL 任务。它只是每档一次的诊断，包含启动、探测、合并与退出开销，不能作为稳定性能结论或与文析宣传画面的绝对速度对比。原始事件和各阶段时间保存在 `TurboDL/_bench/results/maintenance-20261110/turbo-route-diagnostic-01/`。
