这里突然多出来，通常意味着构建里新加了一个产物

更新怎么到达设备应用内「检查更新」
数据来源GitHub Release（与本页同一份）
判据semver 比大小，不看发布时间
提醒方式应用内提示 + 变更说明
下载同样从 Release 附件取，可核对 SHA-256
升级覆盖安装，登录状态与下载任务保留

改脚本不升版本号的话，用户永远收不到更新 —— 判据是版本号

版本号怎么读semver
正式版修 bug、加功能都会升这个号
pre 标记预发布：功能可能还在改，装之前想清楚
判据应用内「检查更新」按版本号比大小，不看发布时间
不可改写同一版本的字节变了会被索引拒绝

改了东西就必须升版本号 —— 这是本项目的硬规则，不是建议

v2.7.20

2026-10-29 · 1 个附件

修复 带提取码的分享解析失败：页面参数里自带一个空的提取码占位（kd 为 0），旧逻辑看到"页面里已经有这个字段"就不再覆盖，把空值提交给服务端，服务端返回"密码错误"。即使用户填对了提取码也进不去。现在只要提供了提取码，就以用户输入的为准。 文件夹分享的识别：新版分享页没有旧版的分页标记，会被当成单文件分享，结果列表为空。现在同时按分享 id 的前缀（文件夹以 b 开头）判断。 验证 用真实公开分享链接实测：无提取码的文件分享与带提取码的文件分享都能正常解析、取直链并完整下载（分别为 875 字节与 166789 字节，字节数一致）。

v2.7.19

2026-10-29 · 1 个附件

修复 连接失效后的等待时间没有按上一版说明生效：应用侧的默认值仍是 60 秒，覆盖了引擎改成 30 秒的新默认值。现在应用默认值与引擎一致。 这一组默认值原来在设置项、设置页"恢复默认"、以及测试里各写了一份，改引擎时三处不会一起动。现在只有一处来源，测试直接与引擎默认值比对，下次再漂移会立刻被测出来。 说明 已手动改过"读超时"的用户仍保留自己的设置，不受影响。

v2.7.18

2026-10-29 · 1 个附件

修复 个人网盘下载文件和文件夹时，取链接前漏掉了一步"提交提取码"，服务端因此返回"请输入密码"，界面上却显示成"提取码错误"——而用户根本没有输入过提取码。现在会按浏览器的方式先提交提取码再取链接。 分享链接里自带提取码时（链接末尾带 pwd 参数），现在会识别出来。此前这一步被丢掉，只能按"无提取码"流程取链接，必然失败。 只提交过一次提取码却被拒绝时才提示"提取码错误"；没有提交过提取码则提示"该分享需要提取码，请填写后重试"，不再一律说成提取码错误。 分享文件夹翻页被拒绝或触发限流时，保留已经加载出来的文件，不再把整个列表判为失败（2.7.17 已包含）。 测试 新增一条用例，覆盖"分享页是否停在提取码表单"的判定。该判定是解锁流程的入口。
