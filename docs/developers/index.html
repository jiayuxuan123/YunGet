写一个解析插件

插件是一段受宿主能力约束的 JavaScript。它把分享信息变成结构化下载源，不接管分片下载，也不直接运行原生扩展。

开始阅读ABI 参考

先看边界，再写代码

宿主只暴露在清单中声明并经用户确认的能力。

  1. 01
    声明协议manifest

    插件说明自己识别哪些协议或链接形态，应用按协议建立索引。

  2. 02
    申请权限capability

    网络、小存储、日志等能力需要写入清单；安装前展示给用户。

  3. 03
    解析与取链runtime

    脚本读取页面或 API 响应，返回文件名、地址和必要请求头。

  4. 04
    交给 TurboDLengine

    分片、并发、续传和本地写入仍由 Kotlin 下载引擎执行。

最小脚本形状

示例只展示入口结构。真实实现请以仓库中的文档与示例插件为准。

parser.demo.js
plugin.protocols = ["demo://"];

plugin.onResolve(async (ctx) => {
  const url = await host.http.request({
    method: "GET",
    url: "https://example.com/file",
  });
  return {
    name: host.path.basename(url),
    url,
  };
});

开发路径

从最小解析器开始，随后补 ABI、签名与发布。

  • 写一个插件插件是一段 JavaScript：能做什么、不能做什么，以及从零写一个能跑的解析器。docs/PLUGIN-DEV.md
  • 插件 ABI 参考脚本能用的每一样东西：plugin / host 两个对象、能力、错误码与所有上限。docs/PLUGIN-API.md
  • 打包与发布清单怎么写、签名怎么算、怎么提 PR 进官方源、怎么自建一个源、怎么发新版本。docs/PLUGIN-PUBLISH.md
  • 插件安全模型信任四级、校验链，以及这份机制不做（也不打算假装做了）的那些承诺。docs/PLUGIN-SECURITY.md

发布前检查

同一版本不得改写字节；改动脚本就要升版本并重新签名。

清单

插件 id、名称、版本、分类、协议与入口必须完整。

签名

对脚本原始字节计算 SHA-256，并使用声明密钥签名。

索引

提交到官方源，或部署一个可通过 HTTPS 访问的静态源。

验证

验证签名只证明发布链一致，不证明代码安全。
