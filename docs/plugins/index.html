插件

云取的插件是一段 JavaScript：不用编译、不用打包 APK —— 写一个 .js 文件，装进应用，启用，它就开始工作。它负责认出链接、算出真正的下载地址、拼请求头、算签名，以及任务结束后做点收尾的事。

插件市场在应用里：设置 → 插件市场。那一页管「哪里能拿到插件」——加源、看源里有什么、从源里装、检查更新；旁边那一行 设置 → 插件 管「本机装了什么」——启停、看运行状态、卸载。

插件不经手下载数据流

这一条是刻意的边界，不是还没做完：插件只在下载任务开始之前和结束之后参与。没有流式 API，没有 body 句柄，没有「每收到一块数据调一次」的回调；插件也不能注册下载后端（试着注册会直接返回 unsupported）。

分片与字节面留在 Kotlin 里，脚本就永远不会站在数据路径上。否则一个写得不好的插件（或者干脆是恶意的）会变成整条下载链路的带宽瓶颈 —— 而且每个数据块都要跨一次 JS 边界，代价比下载本身还大。所以插件的定位是「算 URL / 拼头 / 签名 / 解析分享链接」，不是「自己实现一个下载器」。

怎么装

方式一：在应用里从市场装（推荐）

  1. 云取 → 设置 → 插件市场；
  2. 加一个源：添加源 → 填索引地址 → 选信任等级 → 点「只添加源」。官方源的索引地址是 https://raw.githubusercontent.com/jiayuxuan123/YunGet-Plugins/main/plugins.json；
  3. 源会列出它里面有哪些插件，点进某个插件看权限与信任等级；
  4. 点「安装」—— 装之前会弹一次权限确认，确认之前不下载；
  5. 装完默认就是启用状态，在 设置 → 插件 里能看到它注册了什么、占多少内存。
加源与装插件是两个独立动作：添加源只登记地址、拉取索引，绝不顺手把里面的插件装进来。这样「我从哪拿到这个脚本的」永远是你主动做过的决定，而不是加源时的副作用。

方式二：手动导入一个 .js 文件

  1. 从插件的源码地址下载那个 .js 文件；
  2. 云取 → 设置 → 插件 → 底部 从文件导入，选中它；
  3. 也可以直接 粘贴脚本：粘贴时先点「校验」——校验只解析、不执行，会告诉你它会注册什么、声明了哪些能力。
手动导入的脚本没有签名可验，在插件列表里一律标「未验证」（错误色 + 风险提示）。这不是 bug：没有签名就没有「内容与发布者一致」这条证据。

能力级别：手机上只有一档

插件还有能力级别这一维。它回答的是「这东西能碰到多大范围的能力」以及「改了要不要重启 App」。云取曾经规划过两档：沙箱里的 JS（L1）与宿主进程内的原生代码（L2）。Android 端现在只保留 JS 一档——原生插件在手机端暂时停用，后续出 Windows 版时在 Windows 端启用。

级别运行位置能做什么生效时机
JS 插件
level: "js"		应用内的 JS 沙箱，进程内网盘登录 / 解析 / 取直链、网页与 API 调用、规则与轻逻辑可热加载，装上或更新后立即生效
原生插件（手机端暂时停用）
level: "native"		宿主进程内，Kotlin/JVM 原生代码曾经用来承载新的下载后端、Adapter 与文件 Handler手机端不生效：条目会被拒绝，并说明原因；计划在 Windows 端启用
为什么手机上先停用原生插件：Android 10 起系统禁止加载应用可写目录里的 dex（换到缓存目录也一样被拒），限制一代比一代严；而且首批四个原生网盘插件实际上只是把工作转回宿主既有实现，从没提供过宿主做不到的能力。与其留着一个装不上、或装上也不多给任何东西的档位，不如先在手机上把这一档收起来，等 Windows 端那边不受这条限制时再启用。

索引里没写 level 的存量条目一律按 JS 读；条目写着 native 时，应用会拒绝安装它，并给出「原生插件在手机端暂时停用，后续 Windows 版将启用」这句明确说明 —— 而不是含糊地提示去升级应用。

信任等级：四级都能装，差别在提醒

等级说的是「这个源 / 这个插件的身份可信到什么程度」，四级都能装，差别在界面上怎么显示、低等级时有没有醒目提示。

所以「网盘接口变了要等应用更新」这件事，对内置的那几个成立、对插件不成立

两条不肯让步的规则：

  • 内置公钥只认官方源。判定 official 要「源的身份 + 公钥来源」两个条件同时满足 —— 不能因为某个第三方源用了同一把公钥就把它当官方，那意味着任何人拿到官方签名过的插件就能自建一个「官方源」。
  • 等级只影响显示与提示，不影响校验。无论哪一级，安装都要求 sha256 + 签名齐备。低等级不是「可以少验一点」，而是「验完了仍然要提醒你」。
签名有效只证明脚本内容与某个密钥持有者发布的一致，不证明它安全。它不证明作者是好人、脚本没有恶意行为、没有 bug、不会把你的数据发出去，也不证明它声明的权限是「必要的」而不是「能拿就拿」。同样地，官方源收录不等于绝对安全 —— 官方源的意义是「这个插件经过人工看过、来源明确、出问题能找到负责人」，不是「你可以不看权限就装」。

另外两条实情：用户为该源选的等级优先于索引自称的等级（索引自称高于用户所给时取用户的），所以 fork 一份索引把 trustLevel 改成 official 没有用；自建源被添加时默认就是 community，不是「已验证」。完整的校验链、以及这份机制不做的那些承诺，写在插件安全模型里。

开发自己的插件

插件 API 是一套稳定 ABI：注册解析器与钩子、发 HTTP 请求、算摘要与 HMAC、读写自己的小存储、打日志、用定时器。所有函数、参数与上限都有文档，官方源里那个示例插件就是可以直接照着改的模板。
